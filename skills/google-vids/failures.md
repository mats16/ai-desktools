# When making or updating a video fails

- **HTTP 550 on `save`.** The save was refused and nothing was written. It was seen after many saves in a short time (to the same Vids, and also to other Vids of the same account), and may have come from sessions the client left open (`internal_api.md`). So the client saves few times (one save for all scripts, one for the old scenes, voiceovers eight scenes at a time), and when a save is refused, it waits the seconds the reply gives (`di`), doubling each time up to 5 minutes, and resends up to three times (about 6 minutes in all), adding the voiceovers made meanwhile. If it still fails, check that no tab has the Vids open, wait a while without saving to any Vids of the account, and run again once: if `create` stopped while making the scenes, its Vids is in the trash, so run `create` again (with `--vids`, the Vids is kept; run the same command again); if it stopped while making the voiceovers, run the `update` command it printed. `update` starts from what is saved. When `create` or `update` had to wait, it prints 「保存が 550 で断られ、待って送り直した」.
- **`タブが … に移った` / `タブが閉じられた` / `Chrome との接続が切れた`.** The tab that `vids.py` opened was lost: it moved to another page (for example a sign-in page) or was closed. `create` and `update` open a new tab and go on by themselves; they stop after three lost tabs. Do not open the Vids in the editor while they run, because a save is refused while the same Vids is open in a tab. When they stop, tell the user the reason printed, and run the `update` command printed (or the same `update`) once the Chrome is usable again.
- **`Chrome につながらない` / `Vids を開けない`.** The Chrome is not running with remote debugging, or is not signed in to the target account.
- **`avatar の残りが今月 …`.** The month's avatar generations are not enough for the deck. Tell the user the count, and offer voice only, fewer avatar pages (`none`), or waiting for next month. The avatars made are placed before stopping (also with `create`, whose Vids is kept).
- **`下書きの応答にシーンのコマンドがない`, `音声の応答に一時ファイルがない`, `avatar の応答に生成の ID がない`, `avatar の生成が動画なしで終わった`, or an error from `genai`.** Vids changed its internal calls, or the account cannot use Gemini in Vids. Do not guess new formats from the error; report it to the user with the message, and record what changed in [internal_api.md](internal_api.md) after checking it in the editor.
- After any failure, run `check` before telling the user the video is ready.
