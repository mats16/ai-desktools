# What `create` and `update` do

The mechanics behind steps 5–7 of "Steps" in [SKILL.md](SKILL.md): what each command writes, how long it takes, how it recovers when it stops, and what it records on the Vids. Which command to run when, and what to tell the user, stay in SKILL.md.

## `create`

It makes the Vids in the folder of the Slides, with the name `<Slides の名前>_動画` (`_video` when `[desk] default_language` is not `ja`) unless `--name` is given. It works in two parts, because making the voiceovers takes most of the time and a tab can be lost on the way. First it turns every page into a scene, puts each page's notes as the scene's script, adds the background music that Vids picks, ending with the first scene (`--no-music` to leave it out; without an end it plays to the end of the video), deletes the empty scene that a new Vids starts with, and records the Vids (below); this takes about a minute, and if it stops, the Vids goes to the trash (when the tab was lost, it starts again with a new Vids, up to three times). Then it makes the voiceover of every scene with the chosen voice (with `--avatar`, the avatar video of every scene placed by `--layout`, and a voiceover in the avatar's voice on `none` pages), saving as it goes: new voiceovers eight scenes at a time, each avatar as soon as it is made. Each scene lasts as long as its voiceover or avatar, so the objects, the voiceover, and the scene end together. Around a scene transition that the draft chose (it lies half in each scene), the voiceover of the scene after it starts once the transition is over, and the scene before it gets half the transition after its voiceover. The draft's timed entrances of objects are moved to the start of the voiceover, because they were timed to the draft's own voice. The music is trimmed again to the end of the first scene. If the tab is lost here (it moved to another page or was closed), it opens a new tab and goes on from what is saved, up to three times; if a tab has the same Vids open, it first waits up to 10 minutes for that tab to be closed. If this part stops, the Vids is kept, and it prints the `update` command that makes the rest (the scenes already saved are not made again). Then it reads the Vids back and stops with 「要修正」 unless the scene count, every scene's script, and every voiceover or avatar match the notes and every scene is read by the chosen voice or avatar (`check` does the same with the recorded ones). It records the Slides ID, the mark of the pages, the voice, and the avatar on the Vids file (Drive `appProperties`: `vidsSlides`, `vidsPages`, `vidsVoice`, `vidsAvatar`), so `update` needs only the Vids URL. A 4-page deck took about 90 seconds, and a 38-page deck about 10 minutes (22 minutes of voiceover); an avatar takes about a minute per scene, three at a time. Keep the command in the foreground or in a background job that waits that long.

## `update`

Run it after the notes change (for example after `speaker_notes.py push`). Pass the Vids URL, or the Slides URL to find the Vids made from it by `create` (it stops if there are none or several). It compares each scene's script and voiceover or avatar with the current notes and the recorded voice and avatar (the voice is read from the label of each voiceover, such as 「… - Elio」, and the avatar from the ID of its element), and replaces the script and the voiceover or avatar of the scenes that differ, keeping the other scenes, the music, and edits on screen to the scenes. A replaced scene gets its length again from its voiceover and the transitions around it (`create` above), and when it is the first scene, the music is trimmed again to its end (this drops a trim of the music made on screen); the scenes kept keep their lengths. An avatar keeps its place, also one moved on screen; with `--layout`, avatars whose place differs from the JSON are moved without making them again. `--voice` or `--avatar` (`none` for voice only) records the new choice first and then replaces every scene, so if a voice change stops partway, `update` without it finishes the rest. If adding or changing avatars stops partway, run the same command again with the same `--layout`: scenes already done are kept, and only the rest are made (without `--layout`, scenes still on voice would stay voice only). Switching from voice only to an avatar needs `--layout`, and so does a scene of an avatar video that had no notes and now has some (it has no place yet). In an avatar video, `--voice` alone keeps the avatars and stops unless the voice is the avatar's; avatars are removed only by `--avatar none`. After `update`, also when it stops, the record follows the Vids: if no avatar is left (for example the last avatar page's notes were emptied, or a switch from voice only made none), the video is recorded as voice only, keeping the voice it now has. It stops if the pages changed since `create` (the mark in "When to make or update a video" in SKILL.md), or if the number of pages differs from the number of scenes (step 7 in SKILL.md).

## A new video after pages change

Run `create` again from the same deck (steps 1–5 in SKILL.md; with an avatar, run `layout --reset` first, because the pages changed). When the user asks to clear the video or rebuild the same Vids (same URL and sharing), add `--vids <Vids URL>`: it builds every scene into that Vids, then deletes all it held before (scenes, voiceovers, music, avatars, edits on screen; say first that edits on screen are lost), and records the deck on it. It stops before writing if the Vids records another deck. If it stops while building the scenes, run the same command again (each run deletes all the Vids held when it started); while making the voiceovers, run the `update` it prints. `create` removes the record of the deck from the earlier Vids made from it (printed as 「前の Vids の控えを外した」; with `--vids`, from every other Vids made from it) as soon as the Vids is recorded, and again at the end, so `update <Slides URL>` follows only this one, also when the voiceovers stopped partway and were finished with `update`. Without `--vids`, it removes the record only from Vids made before its own, so when two `create` runs from the same deck overlap, the Vids made last keeps the record. The earlier Vids stays, with its URL, sharing, and edits on screen, and is no longer updated. Tell the user the new URL replaces the earlier one, and move the earlier one to the trash only when they ask.
