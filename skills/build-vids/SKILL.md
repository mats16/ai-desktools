# Build videos from slides (Google Vids, beta)

**Beta.** Vids has no public API for editing. This skill writes a video through the same internal calls the Vids editor makes, from a tab of a Chrome that is signed in to the target Google account. The empty Vids, the MP4, and the record on the file go through the public Drive API, and the notes through the Slides API (`scripts/gapi.py`, a copy of `build-slides`'s, the same authentication as building slides). The internal calls are listed in [internal_api.md](internal_api.md). They can change without notice. All of them are behind `scripts/vids_internal.py` (it runs `scripts/vids_client.js` in the Chrome tab); `vids.py` keeps the commands, the records on the Vids, and the avatar layout, and reaches Vids only through `import vids_internal as backend`. When Google publishes an editing API, write `scripts/vids_api.py` with the same names (`check_closed`, `build`, `fill_and_inspect`, `inspect`, `Lost`; their docstrings say what goes in and out) and change that one import line. The commands and the steps below stay the same. `--browser`, `VIDS_BROWSER`, and `[vids] browser` are settings of the internal backend only. When a step fails with an error from 「Vids の内部 API」, see [failures.md](failures.md).

**Workspace recipes.** The workspace may add to or override this skill in its recipes, which take precedence. Before building, run `python3 scripts/desk.py recipes <material folder>` and open, each whole, the recipes without `step` and with `step: build` whose `description` fits, those the outline's 「使う決まり」 names, and the customer's `memory.md` it names ("Workspace rules" in `desk-feedback` → routing). Skip the ones you already opened in this context.

- [vids-video-001] **Keep every setting of the video reproducible from outside the editor.** The script is the speaker notes ([voice.md](voice.md)); the voice and the avatars are recorded on the Vids by `create` and applied again by `update`. Change the voice, avatars, and music with `vids.py`, not in the Vids editor, because `update` rebuilds changed scenes from the notes and the record, and an edit made only in the editor is lost or contradicted then. When you add a new Vids-only setting (for example how long a scene lasts), record it the same way and have `update` apply it again.

Make the video from the deck itself, and do not copy the Slides into a separate deck for the video, because two decks with the same pages drift apart at every fix and `update` follows only the deck recorded on the Vids. The script of each scene is the page's speaker notes as they are, written as that script by [voice.md](voice.md) when the user asks.

## When to make or update a video

- **Make a video (`create`) only when the user explicitly asks for one,** also while building a deck or fixing it, and do not suggest one. When asked while building a deck, make it right after the notes, without stopping (deck-flow-022 in `deck-workflow` → delivering). A video takes minutes to build (about 10 minutes for 38 pages), and an avatar video uses the month's avatar generations.
- **After the speaker notes change, update the video without asking.** This covers every way the notes change (`speaker_notes.py push`, building the deck again with build-slides, a fix from a comment or a review), when the pages themselves did not change. Run `update <Slides URL>` (step 6): it replaces only the scenes whose notes changed. If it stops with 「この Slides から作った Vids はない」, the deck has no video; do nothing more. If it stops with 「動画を作ったあと、ページが変わった」, the pages differ from those the video was made from (also by a change in an earlier conversation); treat it as the next item. In an avatar video, each changed avatar scene uses one generation; give the count left in the delivery. If the update stops (for example the Chrome is not reachable, or the month's avatar generations are short), still deliver the deck, and say that the video was not updated and why ([failures.md](failures.md)).
- **After pages change** (added, removed, reordered, or what is on a page), do not run `update`, because it replaces only scripts and voices, and the scenes keep the old pages. `create` records a mark of the pages without the notes (`vidsPages`; IDs and URLs are left out, and images are compared by their content), and `update` stops before writing anything when the current pages differ from it, so a later notes-only change does not put new scripts on old pages. Videos made before this mark existed have none and are not checked. In the delivery, say that the video no longer matches the deck. When the user asks, make a new video, or clear the same Vids and build it again from the deck (step 7).

## Setup

- **A Chrome DevTools (MCP) that can reach the target Google account.** `vids.py` connects to that Chrome's remote debugging port, opens a background tab on `docs.google.com/videos`, runs `scripts/vids_client.js` there, and closes the tab. The Cookie and tokens stay inside that tab; the script returns only IDs, counts, and lengths. Use the Chrome that the Chrome DevTools MCP of this conversation drives, if it is signed in to the account that owns the deck. If it is not running, start it the way that MCP's setup says.
- The address is `--browser <URL>`, else the environment variable `VIDS_BROWSER`, else `browser` under `[vids]` in desk.toml, else `http://127.0.0.1:9222`.
- Run with `uv run` (it installs `websockets` and Pillow). `--selftest` also needs `node`.
- The public OAuth token (gcloud ADC) does not work for Vids' editing calls (403, checked 2026-10-21), which is why a signed-in Chrome is needed.

## Scripts

Script paths are relative to this skill's folder; resolve them from there when working in another folder. Run `vids.py` with `uv run` (it installs `websockets` and Pillow) in the material's folder: the settings are found from the current folder upward, else `~/.desk.toml`, `layout --out` defaults to `build/vids_avatar` under the current folder, and the `--layout` path is relative to it. Run `speaker_notes.py` in the material's `build/` folder ([voice.md](voice.md)). `create`, `update`, and `check` take `--browser <URL>` ("Setup").

| Task | Command and result |
| --- | --- |
| Take, check, and write the script | `python3 scripts/speaker_notes.py pull <Slides URL> > notes_vids.json` prints the notes as `{"1": "…"}`; `lint notes_vids.json [--lang ja]` checks them after every edit; `push <Slides URL> notes_vids.json` replaces only the notes ([voice.md](voice.md)) |
| Place avatars | `uv run scripts/vids.py layout <Slides URL> --pages <1,5 or all> [--out build/vids_avatar] [--reset]` writes `avatar_layout.json` and sheets with the circles (step 3) |
| Make a video | `uv run scripts/vids.py create <Slides URL> [--voice Elio] [--name 名前] [--no-music]`; with avatars `--avatar Oliver --layout build/vids_avatar/avatar_layout.json`; into an existing Vids `--vids <Vids URL>` (steps 5 and 7) |
| Update after the notes change | `uv run scripts/vids.py update <Vids URL or Slides URL> [--voice 名前] [--avatar <name or none>] [--layout …/avatar_layout.json]` replaces only the scenes that differ (step 6) |
| Check a video | `uv run scripts/vids.py check <Vids URL> [<Slides URL>]` compares the scenes with the notes and the recorded voice and avatar |
| List voices and avatars | `uv run scripts/vids.py voices` ("Voices"), `uv run scripts/vids.py avatars` ([avatars.md](avatars.md)) |
| Give an MP4 | `uv run scripts/vids.py download <Vids URL> <out.mp4>`, only when asked (waits for Vids to render, up to 10 minutes) |

## Steps

1. **Voice only by default.** Make the video with a Conversational voice (the one the request names, otherwise Elio), and do not ask about the voice or AI avatars. Use an AI avatar only on the scenes the user names explicitly (which avatar: the one named, otherwise the one for the voice), because each avatar scene uses one of the month's avatar generations. Before using avatars, open [avatars.md](avatars.md) (the avatars, the monthly limit, and adjusting them in the editor). Do not suggest avatars or choose their scenes yourself. The other scenes are read by voice only, in the avatar's voice.

2. **Check the notes.** Run `speaker_notes.py lint` ([voice.md](voice.md)) on the deck's notes. If they are not a script yet (no notes, or notes holding sources and supplements for readers), rewrite them in the same deck by the steps of [voice.md](voice.md), and move what readers need from the notes to the source line, the body, or the Appendix of that deck (in the page JSON, then build and lint by `build-slides`). Ask the user before moving anything to the pages. `vids.py` stops if a page's notes are longer than 2,500 characters (Vids' limit per scene). A page with empty notes becomes a scene without voice.
3. **Place the avatar (avatar only).** Run `layout --pages <the chosen pages>` (`all` for every page; the other pages get `none`). It finds, on Google's image of each of those pages, the largest empty corner for a circle (bottom right preferred; on the cover, page 1, it tries larger circles first, up to 0.6 of the page height) and writes `avatar_layout.json` and `avatar_sheet-<n>.png` (the pages with the circle drawn in red, 16 per sheet). Look at every sheet. Fix a page in the JSON when the circle covers or touches text, a figure, a photo, a logo, or a panel, or when it hides what the scene talks about: change `corner` (`br`, `bl`, `tr`, `tl`) or `size` (the diameter as a fraction of the page height, 0.05 to 0.9; make the cover larger or smaller here when the user asks), or set `corner` to `none` for a page that should be read by voice only (for example a full-page figure). Pages with `"check": true` had no empty corner and got the smallest circle at the bottom right; decide each of them. Run `layout` again without `--pages` (it keeps the JSON and redraws) and look again until no page needs a fix. To change which pages have an avatar, run it with `--pages` again: pages already placed keep their place. The check is on the slides' images because the scenes are the same pages; Vids does not need to be open. Adjustments that need the scene itself are made after `create`, on screen ("Adjusting avatars in the editor" in [avatars.md](avatars.md)).
4. **Close the Vids in every browser tab** before `create --vids`, `update`, and `check`, because saving fails with HTTP 550 while the same Vids is open in an editor tab. `vids.py` stops if it sees such a tab in the Chrome it connects to; tabs in other browsers it cannot see.
5. **`create`.** It makes the Vids in the folder of the Slides, named `<Slides の名前>_動画` (`_video` when `[desk] default_language` is not `ja`) unless `--name` is given: a scene per page with the page's notes as its script, the chosen voice or avatars, and background music ending with the first scene (`--no-music` to leave it out). A 4-page deck took about 90 seconds, a 38-page deck about 10 minutes, and an avatar takes about a minute per scene, so keep the command in the foreground or in a background job that waits that long. If it stops while making the voiceovers, the Vids is kept and it prints the `update` command that makes the rest. It reads the Vids back and stops with 「要修正」 unless every scene matches the notes and the chosen voice or avatar, and it records the deck, the mark of the pages, the voice, and the avatar on the Vids, so `update` needs only the Vids URL. Step by step, the timing around transitions, and lost tabs: [create_update.md](create_update.md).
6. **`update` after the notes change** (for example after `speaker_notes.py push`). Pass the Vids URL, or the Slides URL to find the Vids made from it by `create` (it stops if there are none or several). It replaces the script and the voiceover or avatar of only the scenes that differ from the notes and the recorded voice and avatar, keeping the other scenes, the music, and edits on screen to the scenes. `--voice` or `--avatar` (`none` for voice only) records the new choice first and then replaces every scene; if it stops partway, run `update` again (with the same `--layout` for avatars) to finish the rest. Switching from voice only to an avatar needs `--layout`. It stops if the pages changed since `create` (the mark in "When to make or update a video"), or if the number of pages differs from the number of scenes (step 7). Scene lengths, moved avatars, and how the record follows the Vids: [create_update.md](create_update.md).
7. **A new video after pages change, only when the user asks.** Run `create` again from the same deck (steps 1–5; with an avatar, run `layout --reset` first, because the pages changed). When the user asks to clear the video or rebuild the same Vids (same URL and sharing), add `--vids <Vids URL>`, and say first that edits on screen are lost. `create` takes the deck's record off the earlier Vids made from it, so `update <Slides URL>` follows only the new one; the earlier Vids stays, with its URL, sharing, and edits on screen, and is no longer updated. Tell the user the new URL replaces the earlier one, and move the earlier one to the trash only when they ask. Reruns after a stop and overlapping runs: [create_update.md](create_update.md).
8. **Deliver.** Give the Vids URL, the scene count, the voice or avatar, and the total length of the voiceovers that `create` prints. With an avatar, also give how many avatar generations are left this month (printed as 「avatar の今月の残り」). Give an MP4 only when asked (`download`; it waits for Vids to render, up to 10 minutes).

## Voices

`voices` lists the 30 Conversational voices (the display name in Vids, the name of the Gemini voice, and the description on screen). `--voice` takes either name. The default is Elio, the default of the Vids editor. Only Elio and Nyla have been used to make a whole video (2026-10-21); if another voice fails, tell the user which one.

- The Classic voices (Narrator, Educator, and so on) are not supported. They are the only voices offered when making a video from slides on screen, and they read audio tags aloud ([voice.md](voice.md), vids-voice-004).
- The voice shown in Vids' voiceover panel is the user's last choice, not a setting of the video. If the user later presses 「Update voiceover」 on screen, Vids uses the voice in the panel, so tell them to choose the same voice there first.
