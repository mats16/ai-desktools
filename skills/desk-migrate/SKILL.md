# Move a workspace to the current version

Run in the workspace (the folder with `desk.toml`, or `factory.toml` before 2026-10-25; a workspace set in `~/.desk.toml` is found from any folder). `migrate.py` changes only the workspace's own files (`rules/` and `recipes/`, `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `Customers/*/memory.md`, the 「使う決まり」 lines of outlines, `.desk/ledger.jsonl`, `.desk/harness/`, and, when splitting a hand-written index, `references_index.md`, `drive_folders.md`, `Research/references.md`, and empty 「使い道」 cells of ledgers) and takes a backup first, because these hold the user's rules and their history.

```sh
M=<this skill's folder>/scripts/migrate.py
python3 $M check                 # what would move and change. Changes nothing
python3 $M apply                 # backup to .desk/migrate/<time>/, then move and rewrite
python3 $M relink <P-ID> <rules/ file>|--split   # decide where a ledger proposal goes after the split (from 「要判断」)
python3 $M relink-id <ws-ID> <workspace file>|戻さない   # where a workspace rule ID goes when it cannot be decided (from 「要判断」), then remove it
python3 $M to-user               # move <workspace>/desk.toml to ~/.desk.toml and add workspace (see below)
```

## Steps

1. **Check.** Run `check` and show the user the list in one message (what moves, which files are rewritten, and the IDs each file changes as old → new). Do not wait for approval: the backup makes it reversible.
2. **Apply.** Run `apply` and relay its lines as they are (「控え」「移した」「写した」「書き換えた」「番号を替えた」「台帳を合わせた」「移していない」「要判断」).
   - 「番号を替えた」: two earlier workspace rules would have got the same new ID (for example `ws-prompt_doc-001` and `ws-prompt_slides-001` both become `ws-deck-review-…`), so the later one took the next free number. The rule text and the ledger got the same new ID, so their histories stay apart.
   - 「移していない」: the new path already has a file. Open both, merge the old one's rules into the new one, and delete the old one.
   - 「移した: factory.toml」 (2026-10-25): `factory.toml` became `desk.toml` in the same folder (`[factory]` → `[desk]`, `[drive] factory` → `[drive] desk`; the old file is kept as `.desk/migrate/factory.toml`), `.factory/` became `.desk/`, and `rules/factory-<x>/` became `rules/desk-<x>/`. `.gitignore` gets `!/desk.toml` in place of `!/factory.toml`. If the workspace is a git repository, tell the user that `factory.toml` now shows as renamed to `desk.toml`.
   - `rules/dreaming/` → `rules/desk-dreaming/` (2026-10-25): the skill `dreaming` became `desk-dreaming`, and its rule IDs `factory-dreaming-<n>` became `desk-dreaming-<n>` (`ws-` IDs too). The record folder `.desk/dreaming/` and the ledger's `by` value `dreaming` stay. When the workspace has `.desk/dreaming/` and still had the old name, `apply` adds 「要判断: 定期の整理…」: the scheduled cleanup was registered with the old name (the line in `prompt.txt`, or the path of `run.sh` for launchd and cron), outside the workspace, so `migrate.py` cannot fix it. Open `../desk-dreaming/SKILL.md`, then its `schedule.md`, and tell the user to remove the old registration and register again by the steps at its top, because a run that cannot find the old skill or `run.sh` stops without a report.
   - `rules/source-scout/` → `rules/desk-crawl/` and 「移した: .desk/scout/<topic>/ → .desk/crawl/<topic>/」 (2026-10-29): the skill `source-scout` became `desk-crawl`, its rule IDs `source-scout-<n>` became `desk-crawl-<n>`, and `scout.py` became `crawl.py`; `apply` moves the folder and rewrites the names, the `paths`, and the IDs in the workspace files and the ledger. It also converts each topic's records to the new form (states `core` → `follow` and `muted` → `candidate`, kind `gmail` → `gmail-search`, `mode` → a note) and moves them to `.desk/crawl/`, keeping the old folder in `.desk/migrate/scout_<time>/`. It drops the old runs' `misses` (they were children's reading slips; misses now come only from consumers), `feedback`, and each item's `value` (an item readers did not want, value 0, stays used, so it keeps its 「使われた済み」 mark; this gives it credit it did not have before), and does not copy `plan.json`. Once the topics are moved, the whole `.desk/scout/` goes, stray files included. A topic that cannot be read gets 「要判断: … を読めないので移していない」; fix or delete it and run `apply` again. Names in `recipes/` and `CLAUDE.md` are rewritten too. Relay 「要判断: 定期の集め…」: the scheduled prompt is registered outside the workspace, so tell the user to rename the skill in it. A `wiki:` source gets 「要判断」 to re-add it under the wiki service's name (`confluence:` and so on).
   - 「frontmatter を足した」 (2026-10-27): workspace rules are now rule files with frontmatter (`description`, and `paths` for the plugin files whose opening shows them; "Workspace rules" in `desk-feedback/routing.md`). An earlier override `rules/<skill>/<file>` got `paths: [<skill>/<file>]`, so it is shown exactly where it was before, and it stays in place, so the ledger's links to the file still hold. Tell the user that its `description` only names the plugin file, and that it may be rewritten to say when the rules apply.
   - 「要判断: … に frontmatter（description）がない」: a `.md` in `rules/` that is not under a skill's folder (or has frontmatter without `description`) is not shown until it has one (one at a plugin file's path is still shown when that file is opened, with a note). Open it, write `description` (and `paths` if it adds to a step of the plugin; otherwise it is chosen per material in the outline), and run `apply` again.
   - 「台帳をつないだ」「決まりの ID を外した」 (2026-10-27): workspace rules no longer have IDs (`desk-feedback/routing.md` "Routing corrections"). `apply` records which file each `ws-` ID was written in (a `migrated` record in the ledger; `ledger.py` then reads the ID in earlier records as that file, and the earlier lines are not rewritten), removes `[ws-…]` from `AGENTS.md`, `rules/`, and customers' `memory.md`, and records each file's text before and after as a 「移行」 version (`ledger.py undo <P-ID>` puts the IDs back in that file). The user's words, the 「ユーザーが決めた」 marks, and the `c-` and `P` IDs stay. Proposals made before the migration are read without the removed IDs, so they can still be applied and undone.
   - 「手で直した版を残した」「初めの版を残した」 (2026-10-27): the ledger now keeps every version of each rule file. A file where the user had edited the text of an applied proposal (what `ledger.py drift` used to list) becomes a 「手で直した」 version that names those proposals, so `--auto` does not touch it and desk-dreaming keeps those edits when it rewrites the file. The other files get their 「初めの版」.
   - 「要判断: ws-… は、… の 2 つのファイルにある」 or 「… どのファイルにも書いていない」: the findings of that ID cannot be linked to one file (an ID copied into two files, or a rule deleted earlier). Open the files, decide which one holds the rule, and run `relink-id <ID> <file>`; for a deleted rule with no file to link to, `relink-id <ID> 戻さない`. Until then that ID stays in the files, and `check` and desk-doctor keep reporting the workspace as an earlier version. The move to `recipes/` also waits (「要判断: rules/ から recipes/ への移しは…」), because `relink-id` finds the ID in `rules/`; run `apply` again after the last `relink-id`.
   - 「要判断: <file>:<line> が ws-… を指している」: text that names a removed ID without brackets (or any ID in a `.py` file, which `apply` does not rewrite). Rewrite it to say which rule it means in words, or by the file it names.
   - 「写した」 `checks.py`: slides lint reads `slides(p, r)` and document lint reads `doc(doc, r)` from every `checks.py` under `recipes/`. The two copies end in `recipes/slide_checks/` and `recipes/doc_checks/`; delete the function each file does not use.
   - 「移した: rules/… → recipes/…」 (2026-10-29, the last step of `apply`): workspace rules are now recipes (`recipes/<name>/RECIPE.md`, with the templates and checks they use in the same folder; "Workspace rules" in `desk-feedback/routing.md`). Each rule file became its own recipe, named after the file (with its folder's name when two files share a name). `paths` became `step` (`gather` when every plugin file it named is gathering, `build` when every one is building, nothing otherwise, so it is shown at every step of making); a file without `paths`, or whose `paths` named only the per-material-type files (`deck-writing/content_customer.md`, `content_internal.md`, `content_explain.md`), got `per_material: true`. `checks.py` went to `recipes/slide_checks/` and `recipes/doc_checks/`, document templates to `recipes/doc_templates/templates/`, and `rules/README.md` was replaced by the template's `recipes/README.md` (the old one is in the backup). The old paths in the ledger, `.desk/harness/`, `AGENTS.md`, `CLAUDE.md`, `.gitignore`, customers' `memory.md`, other recipes, and the 「使う決まり」 lines of outlines became the new ones, and each rewritten rule file got a 「移行」 version. A path to a file that was not moved stays as it was, and 「要判断: AGENTS.md に前の rules/ のパスが残っている」 quotes such lines: fix each to the recipe it now means. Then tell the user that the recipes are still one per old file, check each `step` with them, and offer to regroup by purpose with `../desk-feedback/recipes.md` §5 (and to move each template and `checks.py` into the recipe it belongs to).
   - 「分ける: references_index.md」 in `check`, then 「控え」「移した」「消した」「作り直した」 (2026-10-29): the overall index `references_index.md` is now rebuilt by `refs.py index` from every `references.md`, and is not edited by hand. `apply` backs up the hand-written one to `.desk/migrate/references_index_<time>.md`, moves its 「Google Drive の置き場所」 section to `drive_folders.md` (kept by hand), and moves the lines whose sources the rebuilt index would not show (a URL only in a ledger's prose or fact table counts as not shown), and the lines without a location (materials decided against, ones without a URL), to `Research/references.md` under the old section headings, as `- ` bullets. A moved line is kept whole there, and each of its URLs and meeting IDs appears in some index line (as for any ledger line). It drops the lines whose every URL and meeting ID the rebuilt index shows. It checks this by rebuilding the index from a copy of the ledgers with the moves applied, and moves any line that would be hidden, until none is. It lists the dropped lines in `references_index_<time>_dropped.md`, with the header lines and old-template format examples it did not move, and copies a dropped line's text into the ledger row when that row's 「使い道」 is empty (ledgers with broken bytes are skipped); the filled rows are listed at the end of the same file. Then it rebuilds the index. Each move is one block ending with the marker line 「<!-- desk-migrate が前の references_index.md から移した。… -->」, and a file that has the marker is not appended to again, so running `apply` again after a stop adds nothing twice. If such a re-run finds lines it would have to move but cannot, it stops with 「要判断: references_index.md を分けていない」 and leaves the old index. To undo the split, copy `references_index_<time>.md` back to `references_index.md`, delete the appended blocks (down to the marker line) from `drive_folders.md` and `Research/references.md`, and clear the 「使い道」 cells listed at the end of `_dropped.md`; the index backup is not in the `<time>/` backup folder. Relay the counts and the backup, and tell the user to skim the dropped list, because the notes a dropped line made across materials are now only there. Also tell them to rewrite the sentences that add to the index by hand in recipes, because `migrate.py` does not rewrite their prose.
   - 「書き換えた」 (2026-10-31): the skills were regrouped by kind (`deck-practices` → `deck-workflow`, `deck-comments` into `deck-workflow` → comments, `slides-template` into `slides-build` → templates, `desk-recipes` → `desk-feedback` with `deck-practices/rules.md` as its routing file, `deck-research` → `desk-research`, the content files into `deck-writing`, the two `visual.md` into `deck-design` as `slides.md` and `docs.md`, the shared scripts into the plugin's `lib/`). `apply` rewrites plugin paths and skill names in `AGENTS.md`, `CLAUDE.md`, recipes, customers' `memory.md`, and the ledger (`RESTRUCTURE` in `scripts/migrate.py`). It does not touch paths under the workspace's `rules/` or `recipes/`, and keeps rule IDs that start with an old name (`deck-comments-001`).
3. **Settle the ledger proposals of split files (「要判断: 台帳の P…」), only if listed.** A full `apply` turns each old file into a recipe with its whole text, so its proposals follow it and nothing is listed. The lines appear only for a workspace an earlier version migrated part way:
   - Proposals in the ledger that target a split file (still to apply, or applied) keep the old `file`, so `ledger.py apply` and `undo` would not find their text. When the text now sits in exactly one other file, `apply` moves the proposal there (「台帳を合わせた」). Rejected, withdrawn, undone, and sent proposals are left alone.
   - 「要判断: 台帳の P… の変更先 …」: the destination cannot be read from the text. Decide it, and record the decision with `relink`, because `check` and desk-doctor keep reporting the workspace as an earlier version until every one is decided:
     - an add proposal not applied yet (no old text): `migrate.py relink <P-ID> <rules/ file>`, the file it should add to (the same file if it still fits there);
     - a proposal not applied yet whose old text moved: `relink` to the file that now holds that text, or withdraw it with `ledger.py withdraw <P-ID>` if it is no longer needed;
     - an applied proposal whose text you split across files: `migrate.py relink <P-ID> --split`. It records the split; that proposal can then no longer be undone (say so in the report). If its text is in one file, `relink` to that file instead.
4. **Check again.** Run `check` (it should print 「移すものはない（今の版）」) and `desk-doctor` (`python3 <desk-doctor folder>/scripts/doctor.py --local`).
5. **Report.** In one message: what moved, the recipes made and their `step`, and the backup folder. Tell the user that deleting the backup is their call.

## Move an AGENTS.md from the old template

When desk-doctor reports 「前の雛形の AGENTS.md」, open [agents_md.md](agents_md.md) and move it with the user (`migrate.py` does not move it).

## Move the settings to `~/.desk.toml`

Only when the user installs the plugin for the whole user, or asks for it (2026-10-25 in `docs/decisions.md`). A workspace with its own `desk.toml` keeps working as it is, so do not suggest this otherwise.

1. Run `to-user` in the workspace. It writes `~/.desk.toml` (the path in `DESK_CONFIG` if set) from the workspace's `desk.toml` with `workspace = "<workspace>"` added at the top, and moves the old file to `.desk/migrate/desk.toml`. Relay its line as it is.
2. 「移していない（… がもうある）」: `~/.desk.toml` already exists. Show both to the user, merge the values they choose into `~/.desk.toml` (keep `workspace`), then move the workspace's `desk.toml` to `.desk/migrate/` by hand, because the two are never merged when read.
3. If the workspace is a git repository, tell the user that `desk.toml` now shows as deleted (the current `.gitignore` template no longer includes it).
4. Run `desk-doctor` from a folder outside the workspace: 「設定」 should be `~/.desk.toml` and 「ワークスペース」 this workspace.

## Notes

- `apply` and `check` can be run any number of times. Files already in the current form are not changed.
- `.desk/migrate/relink.json` (the proposals to a split file that existed at the first migration: those not applied yet, and applied ones whose text was in place; proposals made later are never watched, so a current workspace is not reported as an earlier version) and `relink_done.json` (the decisions made with `relink`) are kept next to the backups. Keep them until the overrides are split; the backup folders themselves can be deleted.
- It does not touch the material folders (`Customers/<customer>/<material>/`, `Internal/`, `Research/`), because they are records of past work, except the 「使う決まり」 line of an outline, which the hook reads, and, when splitting the old index, an empty 「使い道」 in a ledger row and `Research/references.md` (created, or appended to). Other old IDs and paths in an outline or memo stay as they were; look them up in `scripts/ids_*.json` when needed.
- In the ledger, the fields that hold people's own words (`quote`, `a`, `reason`) are not rewritten, so the user's words stay as said; old IDs or names in them stay too.
- The ID maps are `scripts/ids_<date>.json` (`ids`: old → new plugin ID; `prefixes`: old → new prefix, used for `ws-` IDs before they are removed and for plugin IDs no longer in the plugin), applied in date order: `ids_20261024.json` (IDs by topic), `ids_20261025.json` (`factory-dreaming` → `desk-dreaming`), and `ids_20261029.json` (`source-scout` → `desk-crawl`). IDs do not change otherwise (`desk-feedback/routing.md` "Rule IDs"); a future rename adds another dated map.
- To undo, copy the backup folder's contents back over the workspace.
