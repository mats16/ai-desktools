# Move an AGENTS.md from the old template

Until 2026-10-31, desk-init placed `AGENTS.md` and `CLAUDE.md` in the workspace, and corrections were routed into `AGENTS.md`. The plugin no longer reads these files or routes rules to them. Agents load them into every conversation with more weight than a skill, so their rules also applied to work they were not written for. desk-doctor reports a copy of `AGENTS.md` as 「前の雛形の AGENTS.md」 (found by the template's section headings). The ledger does not treat it as a rule file: it keeps no versions of hand edits, and it refuses to link findings to it (`add` or `route --to`, and a proposal with `--src`). A proposal for it without `--src` is accepted and keeps the text before and after for `undo`. The corrections already routed there stay linked to it until you route them to a recipe (step 4). `migrate.py` does not move it, because the file mixes the template's text with the owner's own rules, and only the owner can say which of them should hold in every conversation. Move it with the user.

1. **Take stock.** Back up first with `sh <desk-dreaming folder>/scripts/snapshot.sh save` (it includes `AGENTS.md` and `CLAUDE.md`; `restore` puts them back), because the ledger keeps no version of hand edits to `AGENTS.md`. `python3 <plugin>/lib/ledger.py why AGENTS.md` lists the corrections routed there (with the user's words) and the versions from before 2026-10-31; also `git log -p AGENTS.md` if the workspace is under git. The template's sections are now covered in these places. Use the list as where to look, not as proof:
   - 「いい資料の考え方」: the brief and deck-writing-004 in `deck-writing`
   - 「社外秘と顧客の情報」 and 「書き方」: the sections with the same names in `deck-writing`
   - 「決まりの優先」 (including which workspace rule wins, and filing upstream fixes as Issues): deck-flow-001 in `deck-workflow`, and "Workspace rules" in `desk-feedback` → routing
   - The opening paragraph: `[user] profile` in step 3 of `desk-init`. What the folder is for is the owner's; keep it if wanted
   - 「基本方針」: the language and reuse (step 5 and steps 1–4 of `deck-workflow`), where customer information comes from (`deck-workflow` → gathering materials), building with the Slides and Docs APIs and delivering Drive URLs without PDFs ("Deliverables" in `slides-build`), reading rule files one per call ("Working practices" in `deck-workflow`), the child agent's model (deck-agents-008 in `deck-workflow` → child agents), and when to run desk-doctor or desk-init (their own descriptions). Choosing AI Desk Tools over other slide skills installed in the same environment is the owner's: keep it in `AGENTS.md`, because that choice is made before any recipe is shown
   - 「資料を作る・直すとき」: confirming the four questions before starting (deck-flow-003), reviewing a new material before returning it (step 9, `deck-review`), and requests after delivery (`deck-workflow` → requests after delivery)
   - 「修正の指示」, including 「メモリに書いて済ませない」: `desk-feedback` → recording a correction
   - 「調べもの」: `deck-workflow` → research requests
   - 「フォルダの置き方」: "Workspace layout" and step 5 (git) in `desk-init`, and searching `references_index.md` and `drive_folders.md` first (step 3 of `deck-workflow`). The customers in 「顧客とフォルダ」 are the folders under `Customers/`
   - `CLAUDE.md` (「コンパクションへの備え」): deck-flow-005 and deck-flow-015 in `deck-workflow`. Its 「Compact Instructions」 has no plugin home: Claude Code reads it only from `CLAUDE.md`, so keep it there if the owner wants it
2. **Plan.** Sort every item of both files into one of three:
   - The plugin now says it: delete it only after you have opened the place the list names and found the same point there. If you cannot find it, treat the item as the owner's (the next two).
   - The owner's rule for making materials or gathering, including every correction routed there: move it to a recipe (§1 and §2 of `desk-feedback` → writing recipes).
   - Something the owner wants in every conversation, materials or not: leave it in `AGENTS.md`, which is then the owner's own file.

   Show the plan to the user as a table of item → destination, and wait for agreement, because it changes where each rule appears.
3. **Apply** by the regrouping steps (§5 of `desk-feedback` → writing recipes), with `AGENTS.md` as one of the old files (its proposal takes no `--src`; the ledger refuses it): the `--src` findings move with their items to the new recipes, and the proposal for `AGENTS.md` keeps its text before and after (`ledger.py undo` puts it back). If nothing is left in `AGENTS.md`, ask the user, then delete it. Delete `CLAUDE.md` only when it holds nothing but `@AGENTS.md` and the template's text, word for word; keep anything else in it (such as 「Compact Instructions」), and ask before deleting.
4. **Check.** `doctor.py --local` no longer reports 「前の雛形の AGENTS.md」 (it still does while more than half of the template's section headings remain; rename the sections the owner keeps), and `python3 <plugin>/lib/ledger.py list --to AGENTS.md` prints nothing (link a leftover with `ledger.py route <c-ID> <recipe>`).
